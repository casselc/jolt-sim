# RFC 0001: CEL for cells

Status: accepted for implementation (phase 2, build order item 4).
Design context: [DESIGN.md](../DESIGN.md) "Cells in CEL".

## Purpose

Most cell bodies, every guard and invariant, and the constraint residue that
schema imports leave behind are CEL expressions. The harness needs an OCaml
CEL that is deterministic, bounded before it runs, and confined to what a
cell declares. No OCaml implementation exists, so this one is written
against cel-spec's conformance suite and checked side by side with cel-go.

## Scope

In scope, in this order:

1. **Core CEL** as cel-spec defines it: literals (int, uint, double,
   string, bytes, bool, null), lists, maps, field selection on maps,
   `has()`, the operators with CEL's error and short-circuit rules, the
   conditional, and the standard macros `all`, `exists`, `exists_one`,
   `map` (two and three argument forms), `filter`.
2. **The standard library** functions and overloads: `size`, `contains`,
   `startsWith`, `endsWith`, `matches`, conversions (`int`, `uint`,
   `double`, `string`, `bytes`, `bool`, `dyn`, `type`), `in`, arithmetic
   with overflow errors, timestamps and durations with their accessors.
3. **The cost model**: an actual-cost counter on every evaluation and a
   static estimator over checked expressions, both following cel-go's
   published cost model closely enough that estimates compare.
4. **The type checker** over declared variables and functions, producing
   the checked AST the estimator needs.
5. **The harness extensions** (below), each an expansion into core CEL.

Out of scope: protocol-buffer messages and enums (cells see records from
the type IR of RFC 0003, carried as CEL maps with a declared type), the
`google.protobuf` wrapper types, and CEL's partial evaluation (Cedar does
the partial evaluation the trap needs).

## Values

```ocaml
type value =
  | Null | Bool of bool | Int of int64 | Uint of int64 (* unsigned *)
  | Double of float | String of string | Bytes of string
  | List of value array | Map of value Vmap.t      (* keys: bool, int, uint, string *)
  | Timestamp of Ptime.t | Duration of Ptime.Span.t
  | Type of cel_type
  | Optional of value option
  | Error of error | Unknown of int list
```

- **Int and uint are 64-bit with overflow errors**, never wrapping, as
  cel-spec requires. `Uint` stores the bit pattern; comparisons and
  arithmetic use unsigned operations.
- **Maps are ordered by key.** CEL leaves map iteration order unspecified;
  the harness fixes it (sorted by CEL key order: bool < int/uint by
  numeric value < string by code point) so a cell's output is a function
  of its input. Heterogeneous numeric keys compare numerically, so `{1: a,
  1u: b}` is a duplicate-key error, as in cel-go.
- **Errors and unknowns are values**, absorbed by `&&` and `||` exactly as
  cel-spec's commutative logic says: `false && error` is `false`, `true ||
  error` is `true`, and otherwise an error propagates.
- **Strings are UTF-8**; `size` counts code points; indexing is not offered
  (as in CEL).

## Determinism

A cell's evaluation must be a function of (expression hash, declarations,
inputs). That rules out, and the implementation enforces:

- no `now()`: time enters as an input (`ctx.now`) that the oracle supplies;
- sorted map iteration (above), including in comprehensions and `string()`
  of a map;
- regex: `matches` uses RE2 semantics (linear time, no backreferences);
  patterns are compiled once per expression and must be literals in
  admitted cells, so their cost is known at admission;
- doubles: IEEE 754 with round-to-nearest; `string(double)` uses the
  shortest round-trip representation, matching cel-go's output;
- no host function may read anything not passed to it.

## Cost

Two numbers, as in cel-go:

- **Actual cost** is counted during evaluation: 1 per operator, call,
  select and literal; size-proportional costs for string and list
  operations (`size(x) * 0.1` for string comparisons and `contains`, list
  concatenation by length, comprehensions by iterations times body cost).
  Evaluation stops with `cost_limit_exceeded` when it passes the cell's
  runtime limit.
- **The static estimate** is a (min, max) interval computed from the
  checked expression and size bounds on its inputs. Size bounds come from
  the input types (RFC 0003 carries `maxLength`, `maxItems`,
  `maxProperties` through import) and default to a configurable ceiling
  when a type has none. Admission rejects a cell whose estimated maximum
  exceeds its budget in `gates.edn`-style policy.

**Soundness property, tested with Hegel:** for every checked expression
and every input within its declared size bounds, actual cost ≤ estimated
maximum. A failing case shrinks to a minimal expression and input. This is
the property that makes "bounded before it runs" true, so it gates every
change to the estimator.

## Extensions

Each extension is a macro: it expands to core CEL at parse time, so the
evaluator, checker and estimator never learn new semantics.

| Extension | Expands to | Bound |
| --- | --- | --- |
| `xs.fold(acc, init, x, step)` | a comprehension with accumulator `acc` | iterations = `size(xs)`; accumulator size limited by its declared type |
| `xs.fold_while(acc, init, x, cond, step)` | the same, with `cond` as the loop condition | as `fold` |
| `xs.all(i, x, p)`, `m.all(k, v, p)` and the other two-variable forms | cel-spec's two-variable comprehensions | as the one-variable forms |
| `match v { Tag(x) -> e1; Other -> e2 }` | a chain of conditionals on `v.tag` | checked exhaustive against the variant type |
| `uses lib@sha256:…` and `lib.f(x)` | inlining of the library function's body | the call graph must be acyclic; inlined size is bounded |
| a pure cell called as a function | inlining, as for library functions | the cell must declare no effects |

Host functions (`llm.complete`, `repo.read`, format readers) do not perform
effects: they build intent values (`{kind, args, key}`) that the turn
returns. Format readers (`json.decode`, `csv.decode`) return optionals and
are costed by input length.

## Confinement

An expression can name only the variables and functions its environment
declares. The checker rejects anything else at admission, and the evaluator
has no other bindings to find. There is no `eval`, no reflection, and no
way to reach the host.

## Testing

- **Conformance:** cel-spec's `tests/simple` suite, converted to JSON
  (`cordis/cel/conformance/`). Every test is run; a test the implementation
  does not yet support is reported as skipped with its reason, and skips are
  counted, never treated as passes.
- **Differential:** expressions generated by Hegel from a grammar, evaluated
  by this implementation and by cel-go (`cordis/cel/celgo/`); any
  disagreement in value, error-or-not, or cost estimate is a failure to be
  explained.
- **Cost soundness:** the Hegel property above.
